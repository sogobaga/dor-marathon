# DORPG 怪物「同級玩家 3–4 倍」調參校準（2026-09-19）

本檔合併兩輪唯讀模擬分析（角色 SYNTH／SYNTH2）的結論，供後續維護者查閱決策依據，不重複貼原始
逐筆數據——完整 runs/*.json 與分析腳本留在 scratchpad `dorpg_x3/`（未進 repo）。

## 決策背景

2026-09-19 使用者決策兩項：
1. 怪物基礎能力（HP/ATK/DEF/MDEF）至少是同級參考玩家的 **3–4 倍**——理由：怪物沒有技能、沒有
   裝備，理論上單體強度該遠高於玩家。
2. 六場 `rpg_encounters.power_scale` 資料歸 **1.0**（migration 185）——原本 0.46–0.73 的表是
   P2「power 模式」校準遺物，在等級制（level 模式）公式裡照樣乘進去，會把新 ratio 的效果吃掉，
   且與後台文字「level 模式下不生效」矛盾。

## 公式（P6 契約 §2，Go/TS 兩邊逐位元對齊）

```
hp   = floor(RefPlayer(N).HPMax × monster.hp_mult  × battle_lvl_hp_ratio  × power_scale × slotScale)
atk  = floor(RefPlayer(N).ATK   × monster.atk_mult × battle_lvl_atk_ratio × power_scale)
def  = floor(RefPlayer(N).DEF   × monster.def_mult × battle_lvl_def_ratio × power_scale)
mdef = floor(RefPlayer(N).MDEF  × monster.def_mult × battle_lvl_mdef_ratio × power_scale)
matk = floor(RefPlayer(N).MATK  × monster.atk_mult)   // 不受四個 ratio 或 power_scale 影響
```

`RefPlayer(N)` 是沒有裝備的理論參考玩家（六圍依配點演算法配完、無職業、無 passive）；實際玩家因為
裝備加成，通常比 RefPlayer 強（詳見下方「結構性矛盾」）。

## 方法：兩輪模擬

- **第一輪（SYNTH，單一傭兵）**：矩陣A＝3 職業×6 等級×{none,full}裝×{guard on/off}＝72 列，測 8 組
  設定；判準 a–f：熟練玩家勝率 60–95%、被打 2–15% HPMax、普攻每擊 ≥1.5%怪HP（Lv60 放寬 >0.3%）、
  中位時長 30–180s、Lv60 不可零傷害、三職業差距合理。
- **第二輪（SYNTH2，玩家＋4 傭兵滿編）**：同一矩陣A 72 列，沿用前 7 組設定＋在授權額度內新測 3 組，
  共 10 組；判準放寬：熟練勝率 55–95%（Lv60 放寬至 ≥30%）、被打 2–15%、普攻 ≥1%怪HP、時長
  30–240s、三職業差距 ≤40pt、新手（none+guard off）勝率 ≥20%。
- 全程唯讀分析或用既有 `sim_runner.mjs`/`sim_runner_v3.mjs`，未修改 repo、未 git add/commit、未碰
  資料庫。

## 為什麼沒有一組過關：結構性原因

1. **RefPlayer 比實際玩家弱，「ratio×3」不等於「怪物是實際玩家3倍」**：實際玩家（RefPlayer配點＋
   P7武器＋P8防具）比 RefPlayer 自己強，尤其 DEF 膨脹 1.33×–1.70×（防具主要堆 DEF）。同時六場
   power_scale 原表隨等級遞減（0.73→0.46）且怪物數量／組成隨等級變重，三個因素疊加讓單一全域
   ratio 在低等級與高等級效果完全不成比例。
2. **HP 3 倍會撞 300 秒戰鬥逾時上限，是打不完，不是打不死**：滿隊模擬 `fp2_h3a3_d1`（def/mdef 維持
   1.0）逐列檢查，多個 Lv30–40 列超時率 98–100%，被打%已經健康落在1.8–2.4%（接近判準b下限），問題
   出在玩家+4傭兵輸出速度追不上3倍血量。**DEF/MDEF 是唯一能對抗這個效應而不違反「HP/ATK至少3倍」
   的槓桿**——它只影響「砍穿怪物要多久」這個時間軸，跟 ATK 決定的「被打%」正交；實測把 def/mdef
   從1.0降到0.4，被打%幾乎不變（正交性得證），但(d)通過數5/18→8/18、(a)1/18→3/18、新手勝率
   6/18→11/18。這是最終選 def=mdef=0.4（明顯低於3–4、甚至低於基準1.0）的機制依據。
3. **Lv60 台北101 首領 `hp_mult=7.0` 與全域下限相乘＝有效21倍血量**：首領（DOR-MON-A-67000200001）
   自身 hpMult=7.0 是既有內容設計，跟這次調的全域 battleLvlHpRatio 是兩個獨立倍率、相乘生效——
   一旦全域比例拉到3.0，首領有效血量變成 RefPlayer 的 21 倍（ATK同理變 4.8倍）。不管 DEF/MDEF調多低
   （本輪測過1.5/1.0/0.4/0.4+mdef0.15共4種），Lv60三職業勝率永遠是0%；DEF/MDEF降到能救首領的程度
   會讓Lv10–30小怪徹底沒難度。**這不是四個全域ratio能解的問題**，需要動首領自身hpMult/atkMult
   或重新設計該場次編組，不在本次委派範圍內。
4. **法師 Lv40+ 近乎必敗，非monster端可解**：用非對稱測試（def維持0.4、mdef單獨砍到0.15，等於再砍
   62.5%）排除「monster MDEF太高」假設——技能均傷確實隨MDEF降低提升5–7%，但完全不足以翻轉勝率
   （mage_lv40/60_full 仍是0%）。判定是法師自身在中高等級的輸出/生存力相對其他兩職業有結構性落差
   （跟第一輪單傭兵測試發現的「重騎士明顯比輕騎士/法師耐打，82–92pt落差」同一根因），需要跟角色
   技能/成長曲線一起校準。

## 已知殘留問題（誠實列出，非本次委派範圍內解決）

1. **Lv10–30 熟練玩家勝率100%，超過判準(a)的95%上限**——但被打%（1.7–2.4%）與中位時長
   （77–193秒）皆落在健康區間，屬於「調得動但未找到剛好落在區間內」，非「傷害歸零」式假合格。
2. **Lv60 台北101首領戰三職業勝率恆為0%**——根因見上方原因3，需要另外調整首領自身`hp_mult`/
   `atk_mult`或重新設計該場次編組，非四個全域ratio可解。
3. **法師Lv40起近乎必敗**——根因見上方原因4，需跟角色技能/成長曲線一起校準，非monster端調參可修。
4. 模擬用的玩家技能點固定配置在Lv25那組配點，高等級（Lv50/60）數據可能偏悲觀，非結論本身的誤差
   來源，但解讀高等級數字時應留意。

## 後續建議

若要處理殘留問題1（Lv60首領），建議方向是下修`DOR-MON-A-67000200001`自身`hp_mult`（目前7.0，
與全域3倍相乘後21倍過高）或減少該場次怪物編組（5隻降至更少）；若要處理殘留問題2（法師曲線），
需要開新一輪針對職業技能/成長曲線的模擬，非本檔範圍。兩者都建議先開新一輪SIM驗證再改程式碼，
遵循「交付前驗證：做完才說做完」原則。
